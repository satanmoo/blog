# 2.2 소프트웨어 비유 사용법

## 소프트웨어 비유 사용법

> [!quote] 그렇다면 소프트웨어 비유를 어떻게 사용할 것인가? 그것을 프로그래밍 문제와 프로세스를 이해하는 데 활용하라.

소프트웨어 비유는 코드 한 줄이 특정 비유와 정확히 맞는지 판정하는 도구가 아님

목적은 더 나은 프로그래밍 작업 방식을 떠올리는 것
- 비유를 활용하면 코드를 더 빨리 작성할 수 있다는 것이 저자의 생각

## 소프트웨어 글쓰기: 코드 작성

**글쓰기 비유(writing metaphor)** 는 코드 작성의 개인적 측면을 설명하는 데 유용함.

  글쓰기처럼 프로그래밍도 처음부터 완성된 결과물을 만드는 일이 아니라, 생각을 정리하고 초안을 고치며 표현을 다듬는 활동에 가까움. 하지만 *글쓰기 비유*는 규모가 커질수록 한계가 커짐.

  - 글쓰기는 대개 개인 활동에 가까움
    - 소프트웨어 프로젝트는 서로 다른 역할을 맡은 여러 사람이 함께 참여하는 경우가 많음
  - 글쓰기 결과물은 제출하거나 발송하면 사실상 완료됨
    - 소프트웨어는 출시 이후에도 계속 변경되고 유지보수됨
  - 글쓰기는 독창적인 완성 작품을 만드는 이미지가 강함
    - 소프트웨어 구현에서는 이전 프로젝트의 설계, 코드, 테스트 사례를 재사용하는 편이 더 효과적일 때가 많음
  - 완성 원고보다 버려진 초안 더미에 가까운 면이 있음
    - 좋은 결과는 한 번에 쓰는 것이 아니라 여러 시도와 폐기를 거쳐 만들어짐

## 소프트웨어 농사: 시스템 키우기

**농사 비유(farming metaphor)** 는 소프트웨어를 한 번에 완성된 구조물로 만드는 것이 아니라, 작은 단위로 심고 돌보며 점진적으로 키우는 활동으로 바라보게 함. 이 비유에서 중요한 점은 한 번에 큰 시스템을 완성하려 하지 않는 것

- 먼저 작은 부분을 설계함
- 코드를 작성함
- 테스트함
- 시스템에 추가함
- 이 과정을 반복하면서 전체 시스템을 키움

*농사 비유*는 점진적 개발, 반복, 테스트, 통합의 중요성을 설명하는 데 적합함.

## 소프트웨어 조개 양식: 시스템 증대

**조개 양식 비유(oyster farming metaphor)** 는 소프트웨어 시스템이 작은 핵심에서 시작해 점진적으로 층을 더하며 커진다는 관점을 제공함. 조개가 진주를 만들 때 작은 이물질을 중심으로 여러 겹을 덧붙이듯, 소프트웨어도 처음부터 완성된 전체를 만드는 것이  아니라 핵심 기능 위에 기능과 세부사항을 계속 덧붙이며 성장함.

- 먼저 작고 동작하는 핵심을 만듦
- 그 핵심을 검증함
- 새로운 기능을 한 겹씩 추가함
- 추가한 부분을 다시 검증함
- 반복을 통해 시스템 전체가 커짐

**시스템 증대(system accretion)** 는 이런 식으로 시스템을 점진적으로 키우는 방식임. ^system-accretion

*농사 비유*가 시스템을 돌보고 키우는 지속적 활동을 강조한다면, *조개 양식 비유*는 동작하는 핵심에 기능을 한 겹씩 붙여가며 시스템을 증대시키는 방식을 강조함.

## 소프트웨어 건설: 소프트웨어 구축

*건설 비유*는 *쓰기 비유*나 *농사 비유*보다 소프트웨어의 규모 차이를 더 잘 설명함.

  - 작은 구조물
    - 계획이 부족해도 실수의 비용이 작음
    - 잘못 만들면 고치거나 처음부터 다시 시작할 수 있음
  - 큰 구조물
    - 사전 계획, 설계, 준비가 중요함
    - 실수의 비용이 커짐
    - 여러 역할과 단계가 필요함
    - 변경에는 많은 사람의 시간이 들어감

이미 만들어져 있는 것을 활용
서로 다른 소프트웨어 프로젝트에 서로 다른 개발 접근 방법 사용
소프트웨어 구조에 따라 변경 비용이 달라짐

## 소프트웨어 기업의 적용: 지적 도구 상자

 **지적 도구 상자(intellectual toolbox)** 는 개발자가 여러 기법과 비유를 상황에 맞게 선택해서 사용할 수 있어야 한다는 관점

중요한 것은 도구 자체보다 ==언제, 어떻게 사용할지 아는 판단력==

## 비유 결합

 **비유 결합(combining metaphors)** 은 하나의 비유만 고집하지 않고 여러 비유를 함께 사용해 소프트웨어 개발을 더 입체적으로 이해하는 방식

  비유는 알고리즘이 아니라 발견적 도구에 가까움.

- 서로 배타적이지 않음
- 하나의 비유가 모든 상황을 설명하지 못함
- 여러 비유를 조합하면 각 비유의 약점을 보완할 수 있음
- 팀의 이해나 의사소통을 돕기 위해 상황에 맞는 비유를 선택할 수 있음
