# Books 노트 작성 규칙

이 문서는 `books/` 아래 책 노트의 공통 작성 기준임.

책별로 달라질 수 있는 것은 frontmatter의 두 번째 tag, alias/reference 형식, 제목 언어, 인용 밀도, 용어 목록 정도로 제한함. 책마다 별도 override 문서를 두지 않고, 반복되는 규칙은 이 문서에 공통 규칙으로 반영함.

---

## 1. 디렉터리/파일 규칙

- 경로: `{book-slug}/{NN-chapter-slug}/{NN-NN-section-slug}/index.md`
- 챕터와 섹션 번호는 책의 순서를 따르고, 두 자리 zero-pad를 사용함
- 슬러그는 kebab-case 사용
- 섹션 번호가 책에 명확하지 않으면 노트 작성 순서 기준으로 번호를 부여함
- 서문, 들어가기, 감사의 글처럼 장 번호가 없는 부분은 필요하면 `00-preface` 아래에 둠
- 이미지: 동일 섹션 폴더 안의 `images/{slug}-{NNN}.png`
  - `NNN`은 `001`부터 순번
  - `{slug}`는 해당 섹션의 의미 slug를 기준으로 함

예시:

```text
books/{book-slug}/
  00-preface/
    00-01-preface/index.md
  01-chapter-title/
    01-01-section-title/index.md
```

## 2. Frontmatter

기본 형식:

```yaml
---
tags:
  - books
  - {book-slug}
aliases:
  - {book-specific alias}
references:
  - {book title, chapter, url}
---
```

- `tags`의 첫 번째 값은 `books`로 고정함
- `tags`의 두 번째 값은 책 slug로 지정함
- `aliases`, `references`는 선택 항목이지만, 검색에 도움이 되면 적극 사용함
- alias 형식은 책별로 조정 가능함
  - 장/절 번호를 포함할 수 있음
  - 영문 제목과 한국어판 제목을 함께 둘 수 있음
- references 형식은 책별로 조정 가능함
  - 온라인 원문이 있으면 URL 사용
  - 오프라인 책이면 `Book Title, Chapter N` 같은 서지형 reference 사용

## 3. 제목 위계

- H1: 파일당 1회
  - 책별 기준에 따라 영문 또는 한국어 제목 사용
  - 장 번호나 절 번호가 있으면 제목에 포함함
- H2: 책의 주요 절 제목 또는 H1의 핵심 제목 반복
- H3: 세부 개념, 원칙, 비교 항목
- H4: 한 H3 안에서 case 분기나 비교가 필요할 때만 사용
- H5 이하는 사용하지 않음

절 단위 노트 예시:

```md
# 1.1 Section Title

## Section Title

### Subtopic
```

장 전체 노트 예시:

```md
# 1 Chapter Title

## Main Section

### Subtopic
```

## 4. 본문 작성 흐름

한 개념의 기본 패턴:

1. `> [!quote]` - 책 원문 인용
2. 한국어 설명
3. 필요한 경우 코드 블록, 이미지, 비교, 판단 기준, 추가 quote
4. 필요한 경우 `> [!summary]`, `> [!note]`, `> [!principle]` 등으로 정리

본문 설명은 명사형 종결을 기본으로 함.

- 가장 상위 진술은 `-` 없이 평문으로 작성함
- 하위 개념, 조건, 예시, 반례만 bullet로 들여쓰기함
- 평행한 상위 진술이 여러 개면 각각 평문 줄로 분리함
- 책의 주장을 내 언어로 재구성하되, 책의 논지와 반대로 확장하지 않음
- 개인 의견이나 외부 지식은 최소화하고, 필요하면 `> [!note]`로 책 내용과 구분함

인용 밀도는 책의 성격에 맞게 조정함.

- 개념마다 원문 근거가 중요한 책은 핵심 개념마다 quote를 붙임
- 설명이 길고 반복이 많은 책은 인용할 만큼 중요한 문장만 짧게 가져옴
- 목차용 절이나 독립 노트로 남길 내용이 거의 없는 절은 생략 가능함

## 5. Callout 종류

- `> [!quote]` - 책 인용
- `> [!summary] {제목}` - 핵심 요약
- `> [!note] {제목}` - 보충 설명
- `> [!tip] {제목}` - 실용적 조언
- `> [!warning] {제목}` - 주의 사항
- `> [!principle] {제목}` - 설계/구현 원칙
- `> [!checklist] {제목}` - 실제 점검 항목
- `> [!example] {제목}` - 코드나 상황 예시

Callout 이름은 소문자로 작성함. 제목은 한국어 또는 영문으로 작성할 수 있고, 본문은 한 줄 띄우고 시작함.

## 6. 인용 규칙

- `> [!quote]`에는 책의 핵심 문장만 필요한 만큼 인용함
- 긴 문단 전체를 그대로 옮기지 않음
- 인용은 설명의 출발점으로 사용하고, 바로 뒤에 한국어 설명을 붙임
- quote 블록 내부는 원문 그대로 보존함
- quote 블록 내부에 bold, italic, highlight를 추가하지 않음

## 7. 코드 블록

- 쉘 명령: ```` ```zsh ```` 사용
- 쉘 프롬프트는 `$ ` 포함
- 출력 예시: ```` ```text ```` 사용
- `.gitignore`: ```` ```gitignore ```` 사용
- 언어별 코드 예시는 실제 언어명을 사용
- 책의 코드 예제를 길게 옮기지 않고, 필요한 경우 요지를 보여주는 짧은 예시로 재작성함
- 인라인 backtick은 명령어, 파일명, 옵션, 디렉터리, 클래스명, 메서드명 같은 코드 식별자에만 사용함

예시:

```zsh
$ git status
```

```text
On branch main
```

## 8. 강조 규칙

네 가지 인라인 마크업이 각자 한 가지 역할만 맡음.

- `**bold**` - 새 핵심 개념의 첫 도입
- `*italic*` - 도입된 핵심 개념의 재언급
- `==highlight==` - 문장 안의 핵심 판단 포인트
- `` `backtick` `` - 코드 식별자, 명령어, 파일명, 옵션, 디렉터리

완화된 강조 정책을 적용함.

- 모든 재언급에 italic을 강제하지 않음
- 장이나 절 전체를 관통하는 핵심 개념어에만 첫 도입/재언급 규칙을 적용함
- 번역어가 흔들릴 수 있는 용어는 첫 도입 시 원어를 병기함
- `==highlight==`는 자동으로 남발하지 않고, 작성자가 독자가 놓치면 안 되는 지점에 직접 표시함
- `==highlight==`와 `` `backtick` ``을 겹쳐 쓰지 않음 (Quartz hosting 시 렌더링이 깨짐)
  - 코드 식별자 강조가 핵심이면 backtick만 사용하고 highlight는 빼기
  - 문장의 판단 포인트 강조가 핵심이면 backtick span을 제외한 평문 부분만 highlight로 감싸기

예시:

```md
**정보 은닉(information hiding)** 은 구현 세부사항을 interface 뒤로 숨기는 설계 원칙임.

*정보 은닉*의 목적은 호출자가 불필요한 세부사항에 의존하지 않게 하는 것임.
```

판단 기준:

- "이 장에서 중심이 되는 개념인가?" -> `**bold**`
- "이미 도입한 중심 개념을 다시 가리키는가?" -> `*italic*`
- "이 문장에서 독자가 놓치면 안 되는 판단 지점인가?" -> `==highlight==`
- "코드 또는 코드에 준하는 식별자인가?" -> `` `backtick` ``

## 9. 용어 표기

- 책의 원문 용어와 한국어 번역어가 흔들리지 않게 같은 노트 안에서 표기를 통일함
- 개발 개념은 필요하면 첫 도입 시 원어를 병기함
- 코드 구조 용어는 영어를 유지해도 됨
- 책별로 반복되는 핵심 용어가 있으면 해당 책의 `terms.md`에 고정할 수 있음
- 한국어 번역어가 자연스럽고 널리 쓰이면 한국어 우선으로 작성함
- 영어가 더 정확하거나 코드 맥락과 직접 연결되면 영어를 유지함

## 10. 이미지 임베드

- Obsidian wiki-link 사용: `![[filename.png]]`
- 표준 마크다운 이미지 문법 `![alt](path)`는 사용하지 않음
- 이미지는 같은 섹션 폴더의 `images/` 아래에 둠
- 책의 도표를 그대로 옮기기보다, 필요한 경우 직접 재구성한 다이어그램을 사용함

## 11. 상호 참조와 Anchor

Anchor 이름은 kebab-case 의미명을 사용함.

- 정의: 줄 끝 또는 다음 줄에 `^kebab-anchor-name`
- 동일 노트 내 참조: `[[#^anchor-name]]` 또는 `[[#^anchor-name|표시 텍스트]]`
- 헤딩 참조: `[[#Heading Name]]`
- 타 노트 참조: `[[books/{book-slug}/{path}/index#Section|표시 텍스트]]`

Wiki-link 표기:

- pipe 양쪽 공백 없음: `[[ref|display]]`
- 자동 생성 hash ID anchor 사용 금지
- cross-link 뒤에 "참고" 같은 보조어 첨가 금지
- 절차, 명령어, 핵심 개념이 반복 참조되면 anchor를 부여함
- wikilink 표시 텍스트에 `` `backtick` ``(인라인 코드) 사용 금지 (Quartz hosting 시 wikilink 내부 backtick을 렌더링 못 함)
  - 코드 식별자가 표시 텍스트에 들어가도 backtick 없이 평문으로 적음: `[[ref|git init 실행]]`

## 12. 분량/밀도

- 개념 소절은 quote와 설명 중심으로 짧게 작성함
- 절차/명령어 소절은 anchor, callout, 예시를 충분히 사용함
- 판단 기준이 중요한 책은 principle, checklist, example callout을 사용함
- 책 내용을 누락 없이 망라하되, 반복적인 부연은 압축함
- 나중에 다시 읽었을 때 코드 작성, 리뷰, 개념 회상에 바로 쓸 수 있는 밀도를 목표로 함

## 13. 규칙을 확장하는 방식

새 규칙이 필요해지는 경우:

1. 먼저 해당 노트 안에서 임시로 일관되게 적용함
2. 같은 패턴이 두 번 이상 반복되면 이 문서에 일반 규칙으로 추가함
3. 기존 규칙과 충돌하면 더 읽기 쉽고 재사용 가능한 쪽을 우선함

책별 차이는 이 문서 안에서 일반화 가능한 형태로만 남김.

- [ ] alias/reference 형식이 책 안에서 일관됨
- [ ] H1/H2/H3 위계 준수
- [ ] quote는 필요한 원문만 짧게 사용
- [ ] quote 뒤에 한국어 설명을 붙임
- [ ] 한국어 설명은 명사형 종결
- [ ] 핵심 개념은 첫 도입 bold, 재언급 italic
- [ ] 코드 식별자는 backtick 사용
- [ ] 판단 포인트는 필요할 때만 highlight 사용
- [ ] highlight와 backtick을 겹쳐 쓰지 않음 (Quartz 렌더링)
- [ ] wikilink 표시 텍스트에 backtick 없음 (Quartz 렌더링)
- [ ] 용어 표기가 같은 노트 안에서 흔들리지 않음
- [ ] 이미지는 `images/` 폴더와 `![[...]]` 임베드 사용
- [ ] Anchor는 kebab-case 의미명 사용
- [ ] Wiki-link pipe 공백 없음
- [ ] 개인 의견과 책의 주장을 구분
